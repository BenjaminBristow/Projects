Star award

To get an A+, in addition to the above tasks, you must include the following extra functionality (or at our discretion equivalent advanced features beyond the spec).

As well as outputting the route as a list with changes and lines you should also produce a visualisation of the computed route. 
To do this you should not use any existing graph plotting libraries.
Your journey planner should also be able to account for delays or station closures as well as also include the option of walking between stations as part of the journey.
You should enable a user to input details of any stations that are closed as well as specify delays on lines by inputting new times that it takes to travel between 
stations. You should enable any number of station closures or delays to be specified by the user. The new journeys should be computed based on this new information.
For the option of walking between stations you should use the times given in the provided file walktimes.csv, this file gives a matrix of the times in minutes to walk 
between each station. Here the indivudual station names are given in the first column and row, with the corresponding time to walk between stations given as a cell in 
the matrix (clearer to see if file is opened as spreadsheet, for example opened in excel). Again, to test your code we will use a new file with a new set of walking 
times where the times and stations may differ.
Your journey planner should again compute the shortest time journey and the journey with fewest changes, but this should now include the information on station 
closures and delays as well as the possibility of walking.
